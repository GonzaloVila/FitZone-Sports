# ADR-006 — Framework frontend, librería de componentes y gestión de estado: Vue 3, Vite, TypeScript y Pinia

- **Estado:** Aceptado
- **Fecha:** 2026-09-02
- **Autor:** Mazzulla Santino
- **Sprint:** 1

## Contexto
El sistema FitZone Sports requiere una interfaz web reactiva, moderna y accesible para soportar tanto la experiencia del socio (carnet digital, reservas de clases y canchas, pagos) como los tableros operativos del personal (control de accesos en tiempo real, monitoreo de aforo, gestión de socios y reportes financieros). El equipo contaba con perfiles en proceso de aprendizaje y necesitaba un entorno frontend con compilación ultra-rápida, tipado estricto con TypeScript, una curva de incorporación suave y una solución de estado global que evitara la verbosidad excesiva y el boilerplate.

## Alternativas consideradas
| Alternativa | A favor | En contra | Por qué se descartó |
|---|---|---|---|
| **Vue 3 + Vite + TypeScript + Pinia + Reka UI** | Curva de aprendizaje gradual y excelente ergonomía con Composition API (`<script setup>`); servidor de desarrollo ultra-rápido impulsado por Vite (ESM nativo); Pinia provee estado global reactivo sin boilerplate y con autocompletado TypeScript nativo; componentes headless accesibles (Reka UI) para modales y selects complejos integrados al Atomic Design propio. | Ecosistema de librerías de componentes prediseñados ligeramente menor en volumen que el de React. | **Opción elegida:** Máxima calificación ponderada (4,70/5) por productividad, simplicidad de estado, accesibilidad y velocidad de entrega. |
| **Vue 3 con librería de componentes completa opinada (ej. Vuetify, Element Plus o Quasar)** | Componentes visuales listos para usar de inmediato; menor tiempo de maquetado inicial de controles básicos. | Alto acoplamiento a la estética y estilos del framework; difícil personalización para cumplir con el Atomic Design y tokens de diseño propios de FitZone Sports; bundle size más pesado. | Se descartó a favor de Atomic Design propio sobre primitivos headless sin estilos (Reka UI / Radix Vue) para control total del diseño. |
| **React + Vite / Next.js + Redux** | Ecosistema gigantesco y estándar de facto en la industria; amplia disponibilidad de componentes de terceros. | Curva de aprendizaje más empinada en manejo de re-renderizados innecesarios (`useMemo`, `useCallback`); Redux Toolkit introduce mayor ceremonia y complejidad para el tamaño del equipo. | Menor velocidad de implementación inicial para el equipo y mayor probabilidad de errores de renderizado reactivo (puntuación 4,05/5). |
| **Angular** | Framework completo "baterías incluidas"; arquitectura fuertemente orientada a servicios e inyección de dependencias. | Excesiva complejidad y verbosidad para interfaces livianas; curva de aprendizaje muy pronunciada (RxJS obligatorio para todo el flujo reactivo). | Desproporcionado para los objetivos y plazos del frontend de FitZone Sports. |

## Decisión
Se decidió adoptar **Vue 3** (utilizando Single File Components con `<script setup>` y TypeScript), empaquetado con **Vite**, complementado con **Pinia** para la gestión de estado global y la librería **Reka UI** (primitivos accesibles sin estilos) para componentes complejos como modales, selects y pestañas, debido a su óptimo equilibrio entre velocidad de desarrollo, reactividad transparente y tipado robusto.

## Consecuencias
- **Positivas:**
  - Desarrollo ágil de vistas con Composition API y reactividad nativa predecible sin hooks complejos de memorización.
  - Tiempos de inicio y recarga en caliente (HMR) casi instantáneos durante el desarrollo con Vite.
  - Estado global centralizado y tipado con Pinia para sesión, sede activa y avisos flotantes, sin ceremonia.
  - Base de componentes desacoplada y accesible basada en Atomic Design y tokens de diseño CSS.
- **Negativas:**
  - Menor cantidad de bibliotecas prediseñadas en comparación con React, requiriendo construir algunos componentes base del Design System internamente (`ui/`).
- **Deuda asumida:**
  - Mantener la disciplina en el desacoplamiento de composables para evitar que la lógica de negocio se disperse dentro de los componentes visuales.
